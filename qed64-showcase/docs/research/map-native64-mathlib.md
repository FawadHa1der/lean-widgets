## Risks
- Hard-link aliasing: essential-tree, extra-tree, mathlib4/.lake and two other places share inodes (nlink=5). Any copy made with hard links (cp -al, rsync --link-dest, os.link) followed by a Lake in-place write would corrupt the inputs of the served packs. Use APFS clones (cp -c) only.
- GMP barrel oleans: 151 official-toolchain oleans sit next to native ones in batteries, importGraph and proofwidgets .lake/build. Any staging that sweeps whole package build dirs (rather than a closure selection) would ship files the runtime rejects with 'incompatible header'. Always gate on the flags byte. SelectionPanel (needed by ExprXRay) is one of them and must be rebuilt.
- The widget repo's own .lake builds (elan official toolchain) are all GMP-flagged and must never be packed or put on LEAN_PATH.
- Using any lake/lean other than native/stage1/bin (for example elan's lake in the container, or LEAN_GITHASH set) changes the trace githash. Lake would then try to rebuild all ~3,500 modules, or write GMP oleans.
- OOM: the VM has 7.65 GiB. The original 6-thread build fit, but the MeasureTheory/Probability modules (DistLens delta) were never built in this VM and their peak RSS is unknown. A silent rc-137 kill is possible, and no other Docker job (QED64 bake, kernel build) may run concurrently (RELEASE-PIPELINE.md:101-103).
- Editing the cloned lakefile.lean (R5a) forces Lake to re-elaborate its config. Mathlib module traces are expected to be unaffected, but this is unverified: run the --no-build gate after the edit.
- ProofWidgets widgetJsAll: if widget/js/lake.trace were ever judged stale, Lake would run `npm clean-install` (the errorOnBuild guard is already removed in the clone's lakefile). Under --network none this fails loudly, which is the desired behaviour.
- Patch 0034 lag: the native compiler (857544b439) lacks 0034, so widget oleans compile against the pre-0034 Lean.Environment/Import/Language.Lean/Shell, exactly as the served essential pack does. Widget library code never calls importModules (only the *Tests/ClickE2E files call Elab.processHeader, which must not be shipped), so no ABI mismatch is expected.
- LEAN_PATH first-root-dir rule: delta Mathlib oleans placed in a separate search root (natively or in a browser overlay) are silently shadowed by the essential Mathlib/ root, producing 'unknown module' errors.
- DistLens roughly doubles the work and payload: about 573 extra modules beyond essential, an estimated 0.4 GB raw by extrapolation from extra-tree's 737 modules / 634 MB. That makes it the long pole; consider shipping the other seven first.
- The task premise named 8d91aadcda as the native compiler's commit; the actual commit is 857544b439. The difference is immaterial: there is no compiler source change between them.

- How buffer-probe.cjs boots, types the document, places the cursor, waits and extracts results. (1) `page.goto(url, {waitUntil:'domcontentloaded', timeout:120000})`. (2) It polls `globalThis.qed64.status()` once per second until `phase` matches /^(ready|headerRefused)/, for up to QED64_BOOT_WAIT_S (default 90 s; 900 s for a cold remote site). (3) It types the document with `globalThis.qed64.editor.getModel().setValue(text)`. (4) It places the cursor with `editor.setPosition({lineNumber:L, column:3}); editor.focus()`. (6) It reads diagnostics as Monaco markers via `await import('/node_modules/.vite/deps/monaco-editor.js')` → `monaco.editor.getModelMarkers({resource: model.uri})`, formatted as `line:col sevN message`. ## Risks
- A MakeEditLink or Try-this click into the editor has never been tested in QED64 (no applyEdit in any test or probe). lean4monaco's applyEdit silently returns when `lean.getVisibleLeanEditorsByUri(uri)` is empty or the edit has more than one document (infoview.js:306-316), so a click can look fine and do nothing. Tests must assert that the text changed, not only that the click succeeded.
- Diagnostics from buffer-probe.cjs and widget-probe2.cjs on the production dist shell are always empty, because the vite-only import is swallowed by `.catch`. That is a silent false 'clean'. The Vite dev server, where markers would work, cannot be used because it writes `frontend/node_modules/.vite` inside the read-only repo.
- Each Mathlib-header page costs about 9–10 GB of renderer RSS (HARDENING #44; RESIDENT-WORKER-PLAN:173), and a widget superset snapshot adds more. Running more than two such pages at once on a 36 GB host risks macOS killing the renderer (about 11 GB seen) or slowing every boot. Run lanes serially with the 6 GB cool-down, and always close the browser in `finally`.
- Headers whose roots are not Mathlib, Batteries, MIL or QED64 (e.g. `import IntervalInspector`) boot Init-only and are refused without widening (resident-session.ts:74-78; main.ts:373-387). The overlay snapshot must be named `mathlib`, and test documents need an umbrella-rooted import, or widget modules must sit under a `QED64.*` shim namespace.
- A 'covered' header is resolved by membership in the umbrella snapshot's import list (HARDENING line 243). If the superset snapshot's `imports` or umbrella module does not list the widget modules, the page reports 'refused' even though the oleans are inside the region.
- The page does not check the snapshot↔runtime pairing; only preflight and promote do. A snapshot baked by the native64 compiler at kernel 8d91aadcda (/Users/fawadhaider/code/wasm64-lean-kernel-build-v4.34.0/BUILT-COMMIT) against runtime wasm64-4b025db7729c5f89 (kernel 9fbb45afcb) may load and then trap 'memory access out of bounds' (snapshots.ts:59-65). Run preflight and look for runtime mismatch warnings.
- The ~12 s boot was measured on an otherwise idle machine. Docker or kernel builds running at the same time pushed boots past 400 s (e2e.mjs:88-89), so budgets should be relative or generous.
- The InfoView 'updating' class is the concatenation `non-selectablegold` (no space) in infoview 0.11.1, so `.gold` selectors will not match. Use `[class*=gold]`. A future infoview bump may fix the class and break that selector.
- `addInitScript` re-seeds `qed64.buffer` on every navigation, including reloads, which hides tests of restored-buffer behaviour. Use it only for the first boot, or guard it with a sessionStorage flag.
- The served essential pack has no `ProofWidgets.Component.HtmlDisplay` (06 doc:25; pack manifest). Any widget or test that relies on `#html` needs it inside the overlay snapshot.

# Review of QED64 embedding contract v1 (draft daf9b63, feature/embedding-api)

Written 2026-10-04 by the widgets session (a review agent plus an adversarial checker), answering the draft's §11 questions. Every row cites our code; status: covered / partly / missing / test-only (test-only means only our UX harness or diagnostics use it, the shipped gallery does not).

## Answers to §11

**(a) §10 rows without a v1 equivalent.** (a) Yes, the §10 table (EMBEDDING.md:489-498) is missing several things. Paths: ours are relative to qed64-showcase/ in this repository. QED64's are relative to a worktree of QED64's feature/embedding-api branch (the owner's qed64-wt-embed checkout), where HEAD is now 5a291d3 (65b07e3 = §4 validation; f49e215 = npm exports). EMBEDDING.md is unchanged since daf9b63. The worktree also has uncommitted §7.2 work in lsp-relay.ts, qed64-boot.ts, resident-session.ts and client.ts.

Rows with no v1 equivalent:
1. Liveness.
   - gallery.js:652-686 and 717-718 base behaviour on status().liveness (deferring to QED64, and 'answered' as proof of life). §9 makes it internal (EMBEDDING.md:476) and ApiStatus omits it (EMBEDDING.md:103-114).
   - Our own probe injects LSP requests through relay.fromClient and swallows the replies in toClient (gallery.js:738-806, 559-563).
   - 'Any server frame' counts as proof of life (gallery.js:564-566). It tells QED64's synthetic frames apart only by the label prefix 'QED64:' (gallery.js:132-140), which is not API (EMBEDDING.md:29-31).
   The table row 'tap relay.toClient → events' covers only the stall-progress half of that tap.
2. D3, the getWidgetSource coalescing (gallery/qed64-bridge.js:63-128). The row 'stand down when editorRpc' (EMBEDDING.md:497) would remove it, but D3 is not an editor-RPC defect. Since 47f50e8 the InfoView side runs editorApiOfRpc, so the wire carries startClientRequest/awaitClientRequest (lean4monaco rpc.js:144-156, installed by frontend/build/lean4monaco-fixes.mjs:66-70). The bridge's D3 and D1 paths are keyed on name==='sendClientRequest' (qed64-bridge.js:138-139) and silently stop matching even if we keep the bridge. Meanwhile its D2 handlers still intercept and shadow the native ones (qed64-bridge.js:152, 163, 173).
3. ?mem (gallery.js:1269-1307). The memory knob is deferred (EMBEDDING.md:238-239) and is not in the table. §8's initialBytes hint (EMBEDDING.md:461) is overlay-wide, not per visit.
4. Narrow-screen stacking: CSS on #split/#editor/#infoview plus editor.layout() (gallery.js:488-518), and the #bar offset (gallery.js:382-387). layout is deferred (EMBEDDING.md:238).
5. Restart semantics. gallery.js:630-633 restarts with relay.restartOpts (warmHeader/packs from 'Load exact imports', QED64 main.ts:399). api.restart({snapshots}) defaults to the snapshot list (EMBEDDING.md:147-149), so the table row 'qed64.relay.restart(…) → api.restart({snapshots})' is only partly equivalent. Our own code also skips the relay's header check (reusableOpts, lsp-relay.ts:204-206) and can re-apply stale exact-import options.
6. Cursor: no getCursor (we read it at gallery.js:1482), no focus-only call (gallery.js:1457), and setCursor clamping is unspecified (we clamp at gallery.js:1119).
7. Reload adoption under embed mode. gallery.js:640-645 and 1309-1346 rely on the page restoring qed64.buffer; with embed=1 a reload boots the stale #code= or an empty document (see b).
8. Wait predicates.
   - settled() is unspecified before the first didOpen (the #code= first boot has no version to pass).
   - It may resolve on the transient headerRefused that the page widens by itself (QED64 main.ts:415-425, called from the same status sink at main.ts:435).
   - There is no 'on a session other than X' predicate (gallery.js:1047).
9. Build and deploy tier, absent from the draft:
   - pin-qed64.mjs, deploy-manifest.mjs and build-gallery.mjs read QED64's dist and public layout and scrape the buildId from dist/assets/*.js (pin-qed64.mjs:81-132, 309-311; deploy-manifest.mjs:34-38). The draft only says our dist use is 'unaffected' (EMBEDDING.md:257-258).
   - make-overlay.mjs:5-10 and 33 rename our region to 'mathlib', because the page only loads init/mathlib (resident-session.ts:96, 105, 142). §8 does not say whether other names are allowed.
   - preflight-overlays.sh:50 and 56 run QED64's tests/adversarial/preflight.mjs, which is not in 'files' (EMBEDDING.md:276).
10. Smaller items:
   - the F6 keydown on the page window (gallery.js:1463-1471);
   - whether the page's boot overlay is showing (gallery.js:930-934); status().boot.done is a different fact;
   - progress from page resource entries (gallery.js:914-928);
   - the overlay-index schema, re-root rule and runtime-manifest path behind our preflight (gallery/lib.js:69-137);
   - the liveness timing window behind PROBE_DEFER_MS (gallery.js:80-88);
   - hosting requirements beyond COOP/COEP: no Content-Encoding on chunks, Range for .snapz resume, no HTML fallback (lib.js:16; infra/worker.js:31).

Rows present but needing a caveat:
- fileProgress is 'coalesced to one per animation frame' (EMBEDDING.md:165). rAF pauses in background tabs, while our stall and liveness logic runs on timers (gallery.js:551, 578-605), so a hidden gallery could see no progress and restart a healthy checker.
- §5's iframe allow list (EMBEDDING.md:241-243): ours (gallery/index.html:95) correctly omits cross-origin-isolated for a same-origin frame.
- The late-install note (EMBEDDING.md:500-502) is itself wrong. Its replacement, typeof qed64.api?.status==='function', is true at module start in v1 (EMBEDDING.md:43-47), the same as !!qed64 since 47f50e8. The correct guidance is to stand the bridge down, and drop the warning, when capabilities.editorRpc is true. The same applies to the owner's note that qed64.api.status means 'the relay exists' in v1: §2.1 says the methods are valid before boot, so whenReady() or status().relay is that signal.

**(b) Seed path (#code= + qed64:frame-api).** (b) For the shipped gallery, #code= plus qed64:frame-api is enough, and we do not need the v1.1 init message: we are same-origin and can script the frame (EMBEDDING.md:226-230).

The plan:
- Navigate to /?embed=1&snapshots=snapshots/<overlay>#code=<encodeURIComponent(example)>. This replaces seedBuffer (gallery.js:1066-1080, 1242).
- The boot document is then known before boot, so the header picks light or umbrella directly, with no 5 s window.
- Switches, Reset and 'Open my saved buffer' use api.setDocument, which resolves with the version (identical text re-arms a halted relay, EMBEDDING.md:139-141), then settled({version}).
- Our examples are far below the 2 MiB cap (examples.json is 104 KB for all eight; EMBEDDING.md:206).

Conditions we need written into v1:
1. Reload precedence. location.reload keeps the fragment: the page's #bootreload button (QED64 main.ts:168), our reload fallback (gallery.js:643-644) and a user reload all do. §3.1 gives #code= priority 1 (EMBEDDING.md:185-187), so the page re-boots the original example instead of the edited text, and a setDocument from our qed64:frame-api handler loses to it. Either make #code= read-once (history.replaceState after reading, keeping the query), or let a setDocument made before the boot document is read outrank #code=. We prefer read-once.
2. qed64:frame-api fires once per page document (every reload), only when window.parent is same-origin, before the boot document is read, with detail.frame === iframe.contentWindow. A same-origin cross-realm CustomEvent already reaches parent listeners, so nothing special is needed. The parent must simply not test instanceof CustomEvent.
3. settled() must be defined for the first boot: before any didOpen it resolves on the first ready/headerRefused of the boot document. It must not resolve on a headerRefused the page is about to widen itself (§8; today's widen runs inside the status sink, main.ts:415-425, 435).
4. ?mem still needs a memory knob (gallery.js:1240-1241, 1280-1301); without one it keeps using internals.
5. Embed mode drops the page's persistence (EMBEDDING.md:175), so gallery edits no longer survive a page reload unless the gallery persists them itself from the 'document' event (EMBEDDING.md:163) under its own key.

CORRECTED from the review: the about:blank step (gallery.js:1232-1238) stays. Embed mode removes only the 400 ms save race. The step also frees the old runtime's heap before the next boot (one QED64 per page, EMBEDDING.md:243-245). And with #code= in the src, a src that differs only in its fragment, or an identical src (Retry of the same example), is a same-document fragment navigation and does not boot at all.

What improves:
- We stop writing qed64.buffer, so the user's plain-page buffer on this origin is never displaced again.
- planSave and the saved/history keys (lib.js:28-32, 211-238) then only serve buffers displaced by older gallery versions, so 'Open my saved buffer' keeps reading them and stops writing new ones.
- The stock-page link (gallery.js:410, lib.js:36, no embed) still shows the user's own buffer, which is correct.

Harness: Stock.open (tests/ux/lib/qed64.mjs:545-552) and the bring-up tools and stockcases seed qed64.buffer on the PLAIN page. §3.1 defines #code= only in embed mode, so they need #code= honoured outside embed mode too, or qed64.buffer documented as a test hook.

URL check against §4 (QED64 frontend/src/embed/params.ts:32-63): every URL we build passes.
- The values: snapshots/widgets8, widgets7, nope and ux-unpaired-<pid> (tests/ux/specs/30-robustness.spec.mjs:96, 137), snapshots/rehearsal (gallery/x3.html:24, 59), and the reload-storm tools.
- We never send profiles= or runtime=.
- Our own knobs (?overlay, ?mem, ?liveness, ?stall, ?probe, ?probeTimeout, ?restartGap, ?probeDefer, ?bootTimeout, ?bootStall, ?bootNotice, ?stack, ?pagebar) and the #<pkg> deep links live on /showcase/ and are never forwarded to the frame.
- ?snapshots=snapshots/nope passes validation and fails later as "snapshot 'init' failed to load" (QED64 qed64-boot.ts:134 maps a missing index to null). C8 asserts that label (30-robustness.spec.mjs:104). If v1 makes an unreachable index a named failure, C8 changes.

One breakage from the 47f50e8 semantics, CORRECTED in precision: tests/ux/tools/stockcases.mjs:12 tests if (!q) and then calls q.status(). Between module start and relay construction this throws inside page.evaluate and is caught as {err}. QedDriver.qstatus (qed64.mjs:359) and consoleprobe.mjs:66 degrade to null in the same window, which is harmless.

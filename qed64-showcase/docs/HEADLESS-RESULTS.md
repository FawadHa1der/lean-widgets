## Timings in wasm (predict browser UX)

Measured in the Node wasm worker (same runtime bytes as the browser, but Node's JIT and no
page/Monaco overhead; treat as a lower bound for the browser). Definitions:

* **open → settled**: `didOpen` to `waitForDiagnostics` answered + `fileProgress` drained, with
  the snapshot already loaded (100 ms polling).
* **cursor ms**: what the InfoView waits for after a cursor move on an elaborated document:
  `getWidgets` + `getInteractiveGoals` + `getInteractiveTermGoal` + `getWidgetSource` (first time
  per hash) + the panel's own RPC (`mk_rpc_widget%`).

  progress drained (100 ms polling granularity, so 101/102 ms means "within one poll"). The
  `reElaborationMs` field in each rpc.json adds a fixed 300 ms grace; the native goldens use

### L1 — exported-level imports make non-exposed core definitions opaque to `whnf` (tree-scope Demo:104)

* **What fails.** `#tree_scope (reflect := true) rbSample`, where
  `rbSample : Lean.RBMap Nat String compare := Lean.RBMap.ofList [...]`. TreeScope's
  reflection path (`TreeScope/Reflect.lean`, `classifyNode` → `whnf`) needs to unfold the value
  to constructors; in wasm `whnf` stops at `RBMap.ofList` and `throwNotConcrete` fires. The
  semantic view of the same value on line 101 (evaluation, not `whnf`) works in wasm.
* **Why.** The pinned runtime imports every module at `OLeanLevel.exported`. Kernel
  `wasm64-build/PATCHES.md` §0034: "on Emscripten every import happens at
  `OLeanLevel.exported`… the wasm `.exported` policy is ours". The served worker also hides
  `.olean.private` facets (`lean.worker.js`, `HIDE_PRIVATE_FACETS = true`). Lean core's
  RBMap is `module` code whose definitions are not exposed, so they arrive as **axioms**.
* **Evidence** (probe `rb-whnf.lean`: print the ConstantInfo kind of the RBMap functions, then
  `whnf rbSample`):
  * wasm on the w8 snapshot (`$W/logs/s4-diag-rb-whnf.w8.log`): `Lean.RBMap.ofList: AXIOM`,
    `Lean.RBMap.insert: AXIOM`, `Lean.RBNode.ins: AXIOM`, `Lean.RBMap.empty: AXIOM`,
    `whnf rbSample head = @RBMap.ofList`.
  * wasm with a fresh import from `tree-fat`, which DOES contain
    `Lean/Data/RBMap.olean.private` (`$W/logs/s4-diag-rb-whnf.fat.log`): the same AXIOM lines.
    So staging cannot fix it; the facet is present and ignored.
  * native Lean v4.34.0 (w8 golden LEAN_PATH): `Lean.RBMap.ofList: defn … regular=6`,
    `whnf rbSample head = @Subtype.mk`.
  * native, verbatim tree-scope Demo.lean: rc 0, 0 errors, 0 warnings
    (`$W/logs/s4-E2native-tree-scope.log`).
  * wasm, the Demo with only line 104 removed (`$W/run/diag-tree-scope-no104`): `Demo.olean
    stable at 319072 bytes`, rc 0 (`$W/logs/s4-diag-tree-scope-no104.log`). Line 104 is the
    only wasm difference in that Demo.
* **Not fixable in our repo.** The import level is compiled into the pinned runtime, and
  QED64 must not change. The Demo is the read-only widget source, run verbatim. The showcase
  example `lean/examples/tree-scope.lean` does not use `reflect := true` on a core
  module-system type, and E3 tree-scope passes on both bakes.
* **User impact (document in the gallery).** In QED64, `#tree_scope (reflect := true) v`
  fails with this error when `v`'s definitions live in non-exposed `module` code (e.g. a
  `Lean.RBMap` built with `ofList`/`insert`). The default semantic view works. The same
  policy affects anything that must unfold such definitions by `whnf`/`decide`/`rfl` in
  QED64, which is a QED64-wide property and not specific to the widgets. No showcase example
  or declared click hits it.

Recorded machine-readably in `scripts/headless/known-limitations.json`. The summarizer marks a
failing E2 as root-caused only when its verdict contains that entry's exact error text.
